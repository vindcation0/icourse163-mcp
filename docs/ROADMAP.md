# ROADMAP：答题 / 讨论区 的现状与代价

写这份文档的原因：2026-10-18 做了一轮实测，把很多"未知"变成了"确知"，
原先 HANDOFF 里的能力矩阵已经不足以指导下一步。这里按**已验证事实**重新排优先级。

> 记号：**✅ 已验证**（真跑过）· **⚠️ 代码有但从未 live 验证** · **❌ 未实现** · **🚫 明确不做**
> 代价单位是**人日（0.5 = 半天）**；"风险"指**对账号/课程的副作用**，不是技术难度。

## 0. 现状快照

### 0.1 已验证可用（全部纯 HTTP，无需浏览器）

| 能力 | 证据 |
|---|---|
| 登录（URS 纯 HTTP） | 约 4 秒，`LOGIN_OK`，8 门课 |
| 刷课（签名 RPC） | 约 1.4 秒/单元；分块上报实测 `report_chunks=6`、153 秒 |
| **列待办 `list_todos`** | 纯 HTTP，**159 个**待办（测验 137 / 作业 21 / 考试 1） |
| **读题 `get_homework`** | 纯 HTTP，作业 **0.5 秒**、测验 **3.0 秒**，返回完整结构化试卷 |
| 读卷不消耗次数 | 读前后 `usedTryCount` 都是 `0/10`，`testDraftStatus=0` |
| 次数/时限可预读 | 目录里直接有 `trytime` / `usedTryCount` / `testTime` / `totalScore` |

### 0.2 题目构成（实测，决定了题库到底有没有用）

| 类型 | 实测 | 对题库的意义 |
|---|---|---|
| **作业**（21 个） | 抽 6 个，**全部 `type=10` 主观题**，1 题、0 选项 | ❌ **题库完全无用**，只能 LLM 生成或人写 |
| **测验**（137 个） | 抽 1 份：4 题 = 2×`type=1` 单选 + 2×`type=4` 判断，**4/4 有选项** | ✅ **题库完全可用** |

测验次数：田径 **10 次 / 无时限**；体质健康(新) **3 次 / 限时 1800 秒**。
→ **可以做到"次数不够的卷子不碰"**。

### 0.3 ⚠️ 代码已存在但从未 live 验证

| 能力 | 关键风险 |
|---|---|
| `save_homework_answers`（`submitAnswers` + `preview:true`） | 走的是**不带签名的 JSON POST**；而学习上报接口不带签名会被 `-10006` 拒 |
| `submit_homework`（`preview:false`） | 同上；且 OCS 等成熟项目在 icourse163 上是**点 DOM**，不是调这个 API |

ADR 0003 记的是**设计决策**，不是验证结果。这是整个答题功能唯一的"一票否决"点。

### 0.4 ❌ 已知缺陷（都是读代码/实测发现的）

| # | 缺陷 | 后果 |
|---|---|---|
| D1 | `stripHtml` 只解 `&nbsp; &lt; &gt; &quot;` 与数字实体，**不解 `&rlm;` 等命名实体** | 题库查询串被污染（实测题干里就带 `&rlm;`），匹配率下降 |
| D2 | `session_status` 只要面板 RPC 成功就报 **`可用`**，即使 `course_count=0` | 实测出现过"可用但 0 门课"的半死会话，用户会被误导 |
| D3 | 无**覆盖率闸门** | 题库答不出时也会照常提交，等于交部分答案 |
| D4 | 无**得分回读** | 交完不知道为什么没满分 |
| D5 | 无**答错重做** | 只能"交一次"，拿不到满分 |
| D6 | `type=6` 测验**没有草稿态**（ADR 0003 记录：返回"预览不能提交！"） | 对这类卷只能用 `submit`，不能先草稿 |

### 0.5 ❌ 完全未实现

- **讨论区**：全仓库只有一行注释提到 `contentType 6 = discuss`，且被归类成 `other`。**零代码、零端点知识。**
- **考试代交**：🚫 明确不做（`submitHomework` 硬拒绝 exam，三处文档一致）。

## 2. P0：先修三个已有的坑（**建议立刻做，不必等决策**）

### P0-1 文本清洗（2h）

`homework.ts::stripHtml` 现在只处理 4 个命名实体 + 数字实体。实测题干长这样：

```
&rlm;田径项目主要由 等基本能力项目类组成。 &rlm;
```

要做：
- 命名实体表（至少 `&rlm;` `&lrm;` `&amp;` `&apos;` `&#xNN;` 十六进制）
- 清零宽/双向控制符：`\u200B-\u200F`、`\uFEFF`、`\u2066-\u2069`
- 空白折叠（多空格/换行→单空格）

**为什么先做**：不修的话，题库查询串本身是脏的，P2 做了也白做。

### P0-2 半死会话（1h）

实测：`status` 报 `✅ 可用`，但 `课程数量：0`。真实原因是会话能过鉴权却拉不到课程列表。

要做：`course_count == 0` 时**不报"可用"**，改成明确的"会话异常：鉴权通过但读不到课程，请重新登录"。

### P0-3 文档对齐（1h）

`docs/mcp.md` 里"答题端到端未验证"要改成"**读题已验证，提交未验证**"；
README 的"答题"一节补上"测验是客观题、作业是主观题"这个实测结论 —— 它直接决定用户该期待什么。

## 3. P1：验证提交（**决定答题功能是否成立**）

### P1-A 静态分析前端 bundle（0.5d，零副作用）

目标：回答两个问题
1. `mocQuizRpcBean.submitAnswers` **要不要 `auth-signature`**？
2. 真实 body 形状是不是 `{paperDto, preview}`？

做法：拉 icourse163 的前端 JS（和当初破解 RPC 签名同一套路子），搜 `submitAnswers`，
看它怎么组 header 和 body。**不需要提交任何东西。**

> 参考：这次读 `Samueli924/chaoxing` 的源码发现，超星的答题提交是**纯表单 POST、零签名**；
> 但它在 icourse163 上未必成立 —— 我们的学习上报接口就是必须签名的。

### P1-B 需要签名的话（0.5d）

`src/rpc-sign.ts` 里签名器**已经可用**（算法已破解、有单测），只需把 `submitAnswers`
改走 `buildSignedRpcRequest`。**成本低，因为难的部分早就做完了。**

### P1-C 探明有无"查成绩"接口（0.5d）

P3-C/P3-D（回读 + 重做）依赖它。超星有 `_check_work_result`，我们**完全没有**。
可读卷后看 DTO 里有没有 `userScore` / `score` / `attemptCount` 之类线索，
或者看目录里的 `test.userScore` 是否会更新。

## 4. P2：题库层（**零风险，立刻能产生价值**）

### P2-A `src/tiku.ts`（1d）

采用 **OCS `AnswererWrapper` 的配置格式**（用户能直接粘现成配置），但吸收
`chaoxing` 项目的三处工程化改进：

```json
[{ "name":"...", "url":"http://localhost:5000/search", "method":"post",
   "contentType":"json", "data":{"title":"${title}","options":"${options}","type":"${type}"},
   "handler":"return (res) => res.code === 1 ? [undefined, res.answer] : undefined" }]
```

要实现：
1. 占位符 `${title}` / `${type}` / `${options}` 替换
2. `handler` 求值（`new Function`），返回 `[题,答]` 或 `[[题,答],…]`
3. **多 provider 回退链**（前一个未命中→下一个）
4. **答案类型校验**（抄 `answer_check.py`）：单选答案含强分隔符 → 判定不符 → 舍弃
5. **答案↔选项匹配**（抄 `multi_cut` + 子序列 + 相似度阈值）：题库常返回文本而非字母
6. **本地缓存**（题目文本 → 答案），避免重复计费
7. 全局限速（题库多有 QPS 限制）

### P2-B 菜单接入（0.5d）

`mooc.py` 加一项「测验/作业」：
```
选择卷子 → 读题 → 逐题查题库 → 输出：题号 / 题干 / 选项 / 建议答案 / 命中来源
```
**只输出，不提交。** 用户照着在网页上点。

> 这一步的价值：137 个测验 × 4 题 ≈ 548 题，10 分钟出全部答案。
> 但也要如实说明 —— **手点 548 次不现实**，所以 P2 只是"答案大全"，
> 真正让它成立的是 P3。

## 5. P3：提交与重做（**有写操作，需你确认**）

| 子项 | 内容 | 代价 | 风险控制 |
|---|---|---|---|
| P3-A | 覆盖率闸门：命中 < 80% → 只存草稿不提交 | 2h | 抄 `COVER_RATE` |
| P3-B | 自动填答 + 提交 | 0.5d | **默认 `preview:true` 草稿**；正式提交单独确认 |
| P3-C | 交后回读得分 | 0.5d | 依赖 P1-C |
| P3-D | 答错重做（把错题+正确答案喂回 LLM 重答） | 0.5d | 需卷子允许多次（田径 10 次 ✓，体质健康 3 次 ⚠️） |

**额外要做的安全阀**（建议一并实现）：
- 交前检查目录里的 `usedTryCount` / `trytime`，**剩余次数 ≤ 1 时不自动提交**
- `testTime > 0`（限时卷）时默认不自动提交

## 6. P4：主观题（作业）

**21 个作业全是 `type=10` 主观题**，题库无用。要处理只有两条路：
1. **LLM 生成**（0.5–1d）：接 OpenAI 兼容接口，按题干生成论述答案
2. **你自己写**（0d）

若做 LLM：必须**人工确认后才提交**，且要在输出里标明"AI 生成，请自行判断"。
这类作业通常占分不高但字数要求不低，值不值得做由你定。

---

## 7. P5：讨论区（**独立立项，风险最高**）

| 步骤 | 代价 |
|---|---|
| P5-A 端点发现（抓包或 bundle 分析） | 1d |
| P5-B 实现：读帖 + 抄一条已有回复（超星项目的 4 种策略：不回复/最多出现/最多赞/最新） | 1.5d |

**风险明显高于答题**：
- 回复是**对外公开**的内容，发错不是扣分而是"公开出错"
- 可能有防刷（频率、重复内容检测）
- 讨论区在总评里通常占比很小

**建议**：先确认你那 159 个待办里讨论区到底占多少分，再决定要不要投入 2.5 天。
