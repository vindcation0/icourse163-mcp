### 0.3 ✅ 答题链路已 live 验证（2026-10-18，**原来的一票否决点已解除**）

在 `田径基础知识-单元测验`（`1449647163:1488389457:quiz:1279296073`）上完整跑了一遍：

| 步骤 | 结果 |
|---|---|
| `get_homework` 读卷 | ✅ `paper_type=quiz`，4 题，含 `question_id` + `options[].id` + `supports_save` |
| `save_homework_answers`（`preview:true`） | ⚠️ 逐题 `saved`，但**整体 `rejected`**：「**本试卷不支持草稿预览保存**」 |
| `submit_homework`（`preview:false`） | ✅ `status: "submitted"`，1.3 秒，零错误 |
| **最终得分** | ✅ **8 / 8 满分**，`usedTryCount 1/10`，`isTestChecked=true` |

**三个确定结论：**

1. **`submitAnswers` 不需要签名。** 不带 `auth-signature` 的普通 JSON POST 直接成功 ——
   这否定了"学习上报要签名 ⇒ 提交也要签名"的类推（两者规则不同）。
2. **`preview:true` 对 `test.type=2` 的测验不可用**，服务端明确回"不支持草稿预览保存"。
   所以 ADR 0003 里"先草稿、后确认提交"的流水线**不是通用的**：这类卷只有
   "直接提交"一条路。调用方必须先读 `supports_save`/处理 `rejected`。
3. **答案映射用「选项正文 → 选项 id」是可靠做法**：按 `options[].content` 匹配答案文本，
   再取该选项的 `id` 填 `option_ids`，一次命中满分。**不要写死选项顺序。**

> ⚠️ 这次测试**真实消耗了 1 次作答**（共 10 次），并把该测验做成 8/8 满分。
> 副作用是"有收益"的，但后续任何 live 测试都要先看 `usedTryCount / trytime`。

## 2. P0：先修三个已有的坑（**建议立刻做，不必等决策**）

### P0-1 文本清洗（2h）

`homework.ts::stripHtml` 现在只处理 4 个命名实体 + 数字实体。实测题干长这样：

```
&rlm;田径项目主要由 等基本能力项目类组成。 &rlm;
```

要做：
- 命名实体表（至少 `&rlm;` `&lrm;` `&amp;` `&apos;` `&#xNN;` 十六进制）
- 清零宽/双向控制符：`\u200B-\u200F`、`\uFEFF`、`\u2066-\u2069`
- 空白折叠（多空格/换行→单空格）

**为什么先做**：不修的话，题库查询串本身是脏的，P2 做了也白做。
（**加分证据**：2026-10-18 的实测里题干确实带着 `&rlm;`，而且判断题的 `stem_text` 里还出现
了 `&lrm;` —— 两个都要清。）

> 注意：`option_ids` 是**用选项正文匹配**出来的（见 0.3 结论 3），所以
> `options[].content` 的清洗**同样重要** —— 选项正文脏了会匹配不上。

### P0-2 半死会话（1h）

实测：`status` 报 `✅ 可用`，但 `课程数量：0`。真实原因是会话能过鉴权却拉不到课程列表。

要做：`course_count == 0` 时**不报"可用"**，改成明确的"会话异常：鉴权通过但读不到课程，请重新登录"。

### P0-3 文档对齐（1h）

`docs/mcp.md` 里"答题端到端未验证"要改成"**读题已验证，提交未验证**"；
README 的"答题"一节补上"测验是客观题、作业是主观题"这个实测结论 —— 它直接决定用户该期待什么。

## 4. P2：题库层（**零风险，立刻能产生价值**）

### P2-A `src/tiku.ts`（1d）

采用 **OCS `AnswererWrapper` 的配置格式**（用户能直接粘现成配置），但吸收
`chaoxing` 项目的三处工程化改进：

```json
[{ "name":"...", "url":"http://localhost:5000/search", "method":"post",
   "contentType":"json", "data":{"title":"${title}","options":"${options}","type":"${type}"},
   "handler":"return (res) => res.code === 1 ? [undefined, res.answer] : undefined" }]
```

要实现：
1. 占位符 `${title}` / `${type}` / `${options}` 替换
2. `handler` 求值（`new Function`），返回 `[题,答]` 或 `[[题,答],…]`
3. **多 provider 回退链**（前一个未命中→下一个）
4. **答案类型校验**（抄 `answer_check.py`）：单选答案含强分隔符 → 判定不符 → 舍弃
5. **答案↔选项匹配**（抄 `multi_cut` + 子序列 + 相似度阈值）：题库常返回文本而非字母
6. **本地缓存**（题目文本 → 答案），避免重复计费
7. 全局限速（题库多有 QPS 限制）

### P2-B 菜单接入（0.5d）

`mooc.py` 加一项「测验/作业」：
```
选择卷子 → 读题 → 逐题查题库 → 输出：题号 / 题干 / 选项 / 建议答案 / 命中来源
```
**只输出，不提交。** 用户照着在网页上点。

> 这一步的价值：137 个测验 × 4 题 ≈ 548 题，10 分钟出全部答案。
> 但也要如实说明 —— **手点 548 次不现实**，所以 P2 只是"答案大全"，
> 真正让它成立的是 P3。

## 5. P3：提交与重做（**有写操作，需你确认**）

> ✅ **前提已满足**：提交链路实测可用（8/8），**不需要签名**。P3 从"可行性未知"变成"纯工作量"。

| 子项 | 内容 | 代价 | 风险控制 |
|---|---|---|---|
| P3-A | 覆盖率闸门：命中 < 80% 不提交 | 2h | 抄 `COVER_RATE` |
| P3-B | 自动填答 + 提交 | 0.5d | **必须处理 `rejected`**：不是所有卷都支持 `preview:true` |
| P3-C | 交后读分（目录 `test.userScore`） | **2h**（比原估便宜，接口现成） | — |
| P3-D | 答错重做 | 0.5–1d | 只有**总分**没有**逐题对错**，所以只能"整卷重答"；需 P1-C 才能精准重做 |

**⚠️ P3-B 必须改的一个默认行为**

实测：`preview:true` 在 `test.type=2` 的测验上被服务端拒绝（"本试卷不支持草稿预览保存"）。
所以"**默认走草稿，确认后再提交**"这个安全设计**在这类卷上根本不成立** ——
对它们，唯一的路径就是**直接正式提交**。

要做的是：
1. 先读 `supports_save`，但它**不可靠**（实测 `supports_save:true` 仍被拒）
2. 所以必须**按 `rejected` 的实际响应**做分支，而不是信预读字段
3. 对"无草稿态"的卷：**必须在调用前让人明确确认**，因为交出去就不能只存不交了

**额外要做的安全阀**（建议一并实现）：
- 交前检查目录里的 `usedTryCount` / `trytime`，**剩余次数 ≤ 1 时不自动提交**
- `testTime > 0`（限时卷）时默认不自动提交

## 6. P4：主观题（作业）

**21 个作业全是 `type=10` 主观题**，题库无用。要处理只有两条路：
1. **LLM 生成**（0.5–1d）：接 OpenAI 兼容接口，按题干生成论述答案
2. **你自己写**（0d）

若做 LLM：必须**人工确认后才提交**，且要在输出里标明"AI 生成，请自行判断"。
这类作业通常占分不高但字数要求不低，值不值得做由你定。

## 7. P5：讨论区（**独立立项，风险最高**）

| 步骤 | 代价 |
|---|---|
| P5-A 端点发现（抓包或 bundle 分析） | 1d |
| P5-B 实现：读帖 + 抄一条已有回复（超星项目的 4 种策略：不回复/最多出现/最多赞/最新） | 1.5d |

**风险明显高于答题**：
- 回复是**对外公开**的内容，发错不是扣分而是"公开出错"
- 可能有防刷（频率、重复内容检测）
- 讨论区在总评里通常占比很小

**建议**：先确认你那 159 个待办里讨论区到底占多少分，再决定要不要投入 2.5 天。

## 9b. 已验证的调用顺序（照这个写实现）

```
① get_homework(todo_id)                       → questions[{question_id, type, options[{id,content}]}]
② 逐题算答案（题库或人工）
③ 按 options[].content 匹配出 option_ids       ← 不要写死顺序，实测按正文匹配才可靠
④ submit_homework(todo_id, answers, paper_type)
   ④a 若返回 status="rejected"（不支持草稿预览）→ 说明 preview 路径不可用，直接走 ④b
   ④b submit_homework 正式提交 → 期望 status="submitted"
⑤ 读目录 test.userScore / usedTryCount 验证结果
```

实测耗时：读 3.0s、草稿 1.1s、提交 1.3s —— **单卷全套约 5 秒**。
